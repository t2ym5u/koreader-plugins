# Architecture

This is how the fleet fits together. Read it before changing anything shared.

## Layout

- The monorepo holds about 115 plugins, each a git submodule `*.koplugin`
  backed by its own repo `t2ym5u/<id>.koplugin`.
- `checkers.koplugin` is a fork of `kbarni/checkers.koplugin`. Its `upstream`
  remote points at kbarni.
- There are two shared libraries, both submodules, versioned by git tag only:
  - `game-common/` is used by almost every game and tool.
  - `sudoku-common/` is used by the 8 sudoku variants: sudoku, sudokux,
    windoku, sudokukiller, sandwichsudoku, arrowsudoku, thermosudoku,
    betweenlines.
- In each plugin, `common` is a committed symlink to `../game-common` (or
  `../sudoku-common`). That symlink is for local dev only. On a device,
  `common/` holds real copies, put there by the zip and by Plugin Manager.
- `manifest.json` is generated by `.github/scripts/update_manifest.py`. It is
  the catalogue Plugin Manager reads: files, sha256, zip, category, `retired`.
- `.github/scripts/categories.json` is the only place a plugin's category is
  set. update_manifest.py turns it into `game-common/game_categories.lua`,
  which Tools → Games and Dashboard use.
- `dist/*.zip` is built by `scripts/build_release.sh`. It is gitignored, so add
  the zips with `git add -f`.
- The release CI in each plugin repo (`release.yml`, copied from
  `.github/workflows/release-plugin.yml`) creates a GitHub release on push.

## Plugin anatomy (game-common based)

```
main.lua      PluginBase subclass: name (= dir name), menu_text, menu_hint, party_mode?
              lrequire / lazyrequire / module guard block (see below)
screen.lua    ScreenBase subclass (title bar ☰ / ✕, status line, action bar, rules popup)
board.lua     pure logic (generator, solver, serialize/load), busted-tested
board_widget.lua  drawing (GridWidgetBase)
i18n_fr.lua   { ["English key"] = { fr=, es=, de= } } merged into the global table
_meta.lua     fullname, description, version  (NO `name`: deprecated since KOReader 2026.03)
CHANGELOG.md  "## [x.y.z] - YYYY-MM-DD", top entry == _meta version
test_*_spec.lua   busted specs (never shipped)
images/<id>.png   README screenshot (shipped as an asset)
```

## Loading model

### `lrequire(name)`

Loads a plugin's own module by file path, and caches it in `package.loaded`
under the key `_dir .. name`.

- Plugin-own modules must use this, never `require`. Plain names like
  "board" or "screen" are shared by every plugin and would collide.

### `lazyrequire(name)`, since 2026-11-04

Plugins no longer load their screen or data at KOReader startup.

- KOReader creates every plugin at startup, and creates them again on every
  switch between the file browser and a book. Loading the screen eagerly
  cost about 14 MB of heap for nothing.
- `createScreen()` calls `lazyrequire("screen")`. It prepends the plugin's own
  `?.lua` and `common/?.lua` to `package.path` while loading, because KOReader
  has restored `package.path` by then.
- Big data (word lists, banks, levels) loads when the game opens, for the
  current language only. Its `release()` runs from the screen's
  `onCloseWidget`.
- Each plugin has `test_startup_spec.lua`, which asserts that nothing heavy
  loads at require/init time.

### Shared modules and the module guard (game-common ≥ 1.14.0)

- Each game-common module (`screen_base`, `plugin_base`, `games_menu`, `i18n`,
  `timer`…) lives in ONE `package.loaded` slot, and the first copy loaded
  wins.
- An outdated plugin still installed on the device can therefore impose its
  ancient copy on everyone. In November 2026, arrowwords 1.2.11 crashed every
  game with `getGutter` = nil.
- `common/module_guard.lua` is loaded BY PATH from `main.lua`.
  - `guard.enter()` / `guard.leave()` bracket the requires in main.lua and in
    `lazyrequire`.
  - A registry, `package.loaded.game_common_registry`, records which library
    and version loaded each module.
  - Copies loaded by unregistered (old) plugins, or by older versions, are
    dropped and reloaded from the plugin's own `common/`.
  - When `i18n` is replaced, the old string table is carried over.
- Versions come from `game_common_version.lua` / `sudoku_common_version.lua`.
  **Bump the version and add any new module to `modules` in every library
  release. The specs fail if they drift.**

### i18n

- `require("i18n")` is ONE global table. Every plugin calls
  `i18n.extend(lrequire("i18n_fr"))`.
- A key used by two plugins with different translations is a conflict, and
  whichever plugin loaded first wins. Keep conflicts at 0 with
  `scripts/dev/check_i18n.sh`.
- If the meaning differs, use distinct English keys ("Clear all",
  "Clear key").
- Some standalone tools load their own i18n table with `lrequire` (bookdrop,
  pluginmanager, opdsdir). Even so, keep their keys conflict-free.

## Menus and categories

- **Games:** `PluginBase:addToMainMenu` → `GamesMenu.add`, under
  Tools → Games → <category>.
  - The category comes from game_categories.lua.
  - A brand-new plugin that must land in its category on devices running an
    older table passes `category = "party"` to `GamesMenu.add` itself.
- **Utilities** (quickcalc, converter, stopwatch, almanac, reference,
  dashboard, pluginmanager, bookdrop, opdsdir) override `addToMainMenu` with
  `menu_items.<id> = { sorting_hint = "tools", … }`, so they appear directly
  in Tools. Add their id to `dashboard.koplugin/games.lua` `NON_GAME_IDS`.
- **Party mode:** set `party_mode = true`. The plugin then gets a second entry,
  `<id>:party`, "%1 · multiplayer" (FR « · à plusieurs »), under Party & quiz.
  - `launch_mode` is "solo" or "party".
  - Stats are `last_solo_played`, `last_party_played` and `last_played`.
  - `game-common/party.lua` handles players and teams.
  - `ScreenBase:makeModeRulesButtonConfig` switches the rules text by mode.

## Dashboard

- The home screen opens at startup. It shows continue reading, resume, the
  Daily Challenge, the game grid by category, and stats.
- It scans installed plugins and caches each one's daily kind and
  party-capable flag in `settings/dashboard_daily_cache.lua`, keyed by
  version and mtime.
- Multiplayer tiles are `<id>:party`. They are hidden by default and enabled
  in "Choose games".
- It launches games with `self.ui[id]:showGame(mode)`.

## Plugin Manager

Installs from one zip per plugin, with a per-file fallback.

- `ensureCommon` installs `plugins/game-common/`, then copies it into each
  plugin's `common/`. Shared-lib files are listed automatically from the
  lib's committed HEAD.
- **Retired plugins** are listed in the manifest's `retired` key and in
  `pmlogic.RETIRED_FALLBACK`. Plugin Manager detects them on disk, along
  with `_skeleton`, and deletes them for real. It never installs
  `_skeleton`.
- Since 1.7.2:
  - The settings/manifest cache is shared across instances at module level.
  - `main.lua` is a thin stub; `manager.lua` holds the 103 methods and loads
    on first use.
- Known open issue: it never calls `NetworkMgr:afterWifiAction`, so Wi-Fi
  stays on after installs. That is a possible cause of the "slow until
  restart" report.

## Set-aside / retired plugins

`kakuro`, `arrowwords`, `startmenu`, `boggleparty` and `doubleornothing` are
in `EXCLUDED_PLUGINS`, and their repos are archived. See CLAUDE.md for the
procedure.

- boggle absorbed boggleparty.
- quiz absorbed doubleornothing, as the "Quiz · multiplayer → Rule: Double or
  nothing" rule, and migrates its settings.
- dashboard absorbed startmenu.
